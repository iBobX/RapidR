# RapidR Preview 6 (2.123.0)

- **Faster:** hot code is compiled to machine code while your program runs, and the interpreter itself is 3 to 6 times faster on typed code.
- **Easier to reach:** right-click menus in every part of RapidR Studio (mouse, keyboard and screen reader), and Studio in Brazilian Portuguese and Simplified Chinese (both beta) beside Spanish.
- **Safer, and on more PCs:** Windows 7 and 8 (alpha) and plain Windows XP SP3 (unofficial), the 13 problems four security audits found are fixed, and RapidR still runs classic RapidQ programs as they are.

> **This is a Preview.** Try it and tell us what works, what breaks and what you need: [GitHub Issues](https://github.com/iBobX/RapidR/issues) for bugs, [Discussions](https://github.com/iBobX/RapidR/discussions) for questions and ideas.

Everything in [2.122.1](https://github.com/iBobX/RapidR/releases/tag/v2.122.1) is here. Please read [Behaviour changes](#behaviour-changes): a few mistakes that used to pass in silence are now errors that say how to fix them.

## Fast

**Hot code is compiled to machine code while your program runs.** A loop that turns thousands of times, or a `SUB` or `FUNCTION` called a thousand times, on numbers declared `AS INTEGER`, `AS DOUBLE` and the like, is compiled the moment it is hot. It happens in Studio's Run (F5), in `rapidr run` and in interpreted apps, on 64-bit Windows, macOS and Linux. There is nothing to switch on and nothing to change: the answers, the run-time errors and the line they name are the same. Typical loops and routines run 4 to 20 times faster than interpreted, close to a native build ([the manual](docs/manual/cli-and-runtime.md#hot-code-compiled-the-jit), example `examples/basics/hot_loops.rr`).

Measured with `rapidr run` on an Apple M4 Max, the fastest of 5 runs:

| Program | 2.122.1 | 2.123.0 | A native build |
|---|--:|--:|--:|
| 10 million loop turns | 553 ms | 16 ms | 23 ms |
| 2 million calls of a function | 355 ms | 6 ms | 13 ms |
| A synthesizer's 1.4 million voice steps | 310 ms | 10 ms | 5 ms |

[check: the 2.122.1 column is from docs/speed-audit-2026-11.md ("Phase 2" table, the "before" column) and the 2.123.0 column from docs/jit-design.md §12.5; two sets of runs on the same Mac. Re-run `python3 tools/bench/vm_vs_native.py --runs 5` on the release build and update the numbers before publishing.]

**A real program: a Z80 computer emulator written in RapidR.** One emulated frame cost 14.4 ms of CPU and costs 0.6 ms now (a native build: 3.7 ms), so it runs 50 frames a second instead of 23. The JIT now compiles `IIF`, a `DIM` inside one branch of an `IF` or `SELECT CASE`, comparisons used in arithmetic, and routines that only rarely go back to the interpreter. A music app's audio engine voice loop is 5 times faster. `rapidr run --verbose` now names each loop or routine it left interpreted, with its file and line and the statement that keeps it there, so you can see what a hot routine needs (example `examples/basics/hot_cpu.rr`).

**The interpreter itself is faster, everywhere**, also on the web and on 32-bit Windows, where the JIT is not built. Typed code runs 3 to 6 times faster:

| Program | 2.122.1 | 2.123.0 |
|---|--:|--:|
| 10 million loop turns | 553 ms | 120 ms |
| the same inside a `SUB` | 559 ms | 91 ms |
| 2 million `INTEGER` array elements written, read and summed | 315 ms | 84 ms |
| A synthesizer's voices in global `DOUBLE` arrays | 787 ms | 241 ms |
| The 10 million loop under the debugger | 646 ms | 232 ms |

Text and file work is not faster: that time is spent in the runtime, as before. Programs built before still run; a bytecode file (`.rrbc`) made by 2.123.0 needs the 2.123.0 Runtime.

**Native builds keep arrays of numbers as plain memory.** An array declared `AS BYTE`, `WORD`, `SHORT`, `INTEGER`, `LONG`, `DWORD`, `SINGLE`, `DOUBLE`, `INT64` or `UINT64` and used by its elements is a plain vector in a native build. A synthesizer keeping its voices in global `DOUBLE` arrays went from 131 ms to 8 ms; 2 million `INTEGER` elements written, read and summed from 42 ms to 12 ms. A 32-voice synthesizer computes a 10 ms block of sound in under 0.1 ms. Programs do the same in every runtime ([the manual](docs/manual/language.md#fast-arrays-in-native-builds), example `examples/basics/fast_arrays.rr`).

**RapidR Studio never waits for the code check.** The problems, the colours of your names and the Outline are made on a thread of their own and shown when they are in. A pause in typing cost the UI 52 to 75 ms in a 5,000-line program and over 1.5 s in a 17,800-line Win32 header; now its longest stretch is 5 and 15 ms. With 2,000 problems a pause costs 6 ms instead of 0.8 s. In the browser, a caret move in a 5,000-line program takes 19 ms instead of 65 ms, and dragging a window with 200 controls takes 13 ms a step instead of 30 ms.

**Speed is now checked.** The tests hold the interpreter and the user interface to a speed budget for each benchmark, so a change that makes them slower fails before it ships.

Where the JIT is not yet: the web and 32-bit Windows run everything interpreted (with the same answers). See [Known limits](#known-limits).

## New in RapidR Studio

- **Right-click menus everywhere** ([the manual](docs/manual/right-click-menus.md), [design](docs/context-menus-design.md)). A file, folder or the project in the Project tree, a document's tab, the code, a component on a form, a property or an event, a chat in the Assistant, a problem, a line of output, a value while debugging, a call, a breakpoint, a Help page, the status bar, a pane's tab, a recent project, a Toolbox item. The menu is the same on every system and every menu follows the same rules: the default action first and in bold, the keys shown, the groups always in one order, what loses something last. An item you can't use is greyed and says why in a small tip (a screen reader reads it). **Shift+F10**, the **Menu key** and a screen reader's "show menu" open the same menu under the selected item. A problem in the code offers its fix first ("Change to Caption"); a line of output that names a place offers "Go to main.rr, Line 12". "Ask RAI About..." puts the file, code or problem in the question box and never sends by itself.
- **RapidR draws these menus itself**, in Studio's look, so RAI and AI apps can see them and pick from them.
- **The Project tree** gains Compare With (the version on disk, the last version, another file) and Delete File, which asks first and sends the file to the system's Trash, never the main file and never a file outside the project's folder.
- **The Assistant's chats** are grouped by Today, Yesterday and Earlier, renamed in the row itself, and can be copied as Markdown. Small Rename, Delete and More buttons appear on the row under the mouse and on the selected row, with F2 and Del too.
- **RNotify and RNotifyBar** [pending: the NOTIFY lane has not landed and `docs/manual/notifications.md` is not on disk. Fill this from that page: what the compact strips look like, how a program uses `RNotify` and `RNotifyBar`, where Studio uses them, and the manual link.]
- **Document tabs that keep their names** when many are open [pending: same lane. Say what the tabs do (names, scrolling, the list of open tabs) once it lands.]
- **RAI and AI apps share one tool set** ([docs/ai-tools.md](docs/ai-tools.md)). Every tool of Studio is defined once and both get it, under the same permission rules. RAI can now look at what Studio has open, read the program's output, debug, set a property and keep versions; AI apps get the Versions tools RAI had. New for both: `save_version`, `list_versions`, `compare_versions`, `restore_version`, `start_versions`, `how_do_i` (the steps for a task) and `report_gap` (a line in `RAPIDR-ISSUES.md` when a tool or an answer is missing). `app_click` with `menu` picks an item of any menu by name, a pop-up menu's too.
- **AI agents are told the RapidR way, even small ones**: twelve numbered rules on connect and in RAI's instructions (for example, never a shell for your project's history: use the Versions tools), two ready-made MCP prompts and three guides to read.
- **A program's window that stops answering is said, with where.** Run from Studio or `rapidr run`, a window that has not answered for 5 seconds gets a hang report on your computer and a line in the Output with the file, line, `SUB` and event ("A long loop needs a DOEVENTS now and then"). Nothing is sent anywhere.
- **Small things**: Ctrl+F4 closes a document again beside Ctrl+W on Windows and Linux; Project > Add File... is now **Add Existing File...**; menus in RapidR's looks have 24-pixel rows (20 in the classic look), easier on touch and the web.

## New components and features

- **`RMIDIPort`: MIDI in and out, with SysEx, on every system** ([the manual](docs/manual/directx-and-media.md#midi-in-and-out-rmidiport), examples `examples/media/midi_monitor.rr` and `examples/media/midi_sysex_port.rr`). It lists the MIDI keyboards, controllers and synthesizers, opens an input and an output by number or by name, and tells your program what arrives with events on their own thread, in order: `OnMessage`, `OnNoteOn`, `OnNoteOff`, `OnControl`, `OnSysEx` with a whole SysEx message however many pieces it came in, `OnDevicesChanged`, `OnError`. It sends notes, controls, programs and SysEx (`SendHex "F0 7E 7F 06 01 F7"`). Every byte is checked before it goes out and every mistake is said in plain words. SysEx is off until the program asks for it. In the browser, RapidR asks only when the program first uses a device, says why first, and asks for SysEx separately.
- **`RFormEx`, a form with more** ([the manual](docs/manual/forms-ex.md), example `examples/gui/form_ex.rr`): files dropped on it one by one, its own system tray icon, the whole window see-through or its background a hole for the desktop, stay on top, `OnMinimise`, and the window's messages. Programs that use the classic `QFormEx` include now run unchanged. See-through and the hole work on Windows, macOS and the web, not on Linux yet.
- **`MOVETOTRASH(Path$)`**: a file or folder to the system's Trash, where it can be put back (macOS' Trash, Windows' Recycle Bin, the desktop's Trash on Linux). It gives True when it went. A browser has no Trash and says so ([the manual](docs/manual/language.md#to-the-trash-movetotrash), example `examples/basics/trash.rr`).
- **Big numbers** ([the manual](docs/manual/big-numbers.md), example `examples/basics/bits_and_64bit.rr`). An `INT64` or `UINT64` keeps its type and every digit wherever it goes: a `VARIANT`, an array, a `TYPE` field, a parameter, a property, files, streams, `RJson`, SQLite and MySQL parameters, the debugger. New: **`UINT32`**, **`LOWORD`**, **`HIWORD`**, **`LOBYTE`**, **`HIBYTE`**, **`GETBITS`**, **`SETBITS`** and **`HEX$(x, digits)`**. The five items promised in 2.122.1 are done: a `FOR` loop's end test is exact and a 64-bit counter stops at its type's end, `SELECT CASE` and `INPUT` are exact, `FORMAT$` shows a 64-bit value whole, and a `UINT64` joined to text with `&` or `+` shows unsigned. The same on the interpreter, native builds and the web.
- **Memory a DLL writes later now reaches your program** (Windows). A driver filling a `MIDIHDR`, a `WAVEHDR` or an `OVERLAPPED` after the call returned is seen at the next event handler, wait (`DOEVENTS`, `SLEEP`, `ShowModal`) or DLL call; a SysEx MIDI receive program works on Windows. A `SUB` that hands a local `TYPE` to a DLL 100,000 times took 16 s and could run out of addresses; it now takes 1.3 s ([the manual](docs/manual/language.md), docs/windows-dll-calls.md §7).
- **`RSystemInfo.OSVersion` says the Windows it really is**: "5.1 (2600)" on XP, "6.1 (7601)" on Windows 7, "11 24H2 (26100)" on Windows 11.
- **Right-click events for your programs** ([the manual](docs/manual/right-click-menus.md)): `OnContextMenu (X, Y, Key)` on every component that can take the keyboard (a right click, Shift+F10, the Menu key or a screen reader's "show menu"), `RListBox.ContextIndex`, `RListBox.RowActions` and `OnRowAction` (icon buttons on a list's rows), `RListBox.Heading(i)`, `RMenuItem.Default` (bold), and `RPopupMenu.SystemMenu` (False: RapidR draws the pop-up in the program's look). Example `examples/gui/context_menus.rr`.
- **The mouse wheel works on painted lists and scroll bars**: `OnMouseWheel (Delta, X, Y, Shift)` on a form, panel, scroll box, group box, bevel, label, image or canvas, and in a RapidR program the wheel over an `RScrollBar` moves it ([the manual](docs/manual/components.md#the-mouse-wheel), example `examples/gui/wheel_list.rr`).
- **`RLanguageService.Analyze`, `Ready` and `OnAnalyzed`**: a program starts the check of its code away from its own work and hears when it is done ([the manual](docs/manual/studio-editor.md#in-your-own-programs-rlanguageservice), example `examples/studio/language_service.rr`).
- **`RMcpServer.AddAlias` and `AddPrompt`**: a renamed tool keeps answering its old name; a program offers ready-made instructions to an AI app's person.

## Old PCs

RapidR's aim is that it runs on old and cheap computers too. Two downloads are new in this release.

**Windows 7, 8 and 8.1 (alpha).** `RapidR-2.123.0-win7-x86-alpha<N>.zip` [check: alpha number; and confirm it is still labelled alpha]. RapidR Studio and interpreted programs for 32-bit Windows 7, 8 and 8.1 (the programs also run on 64-bit editions). Unzip it and run `RapidR-Studio.bat`; nothing to install. These systems are out of Microsoft's support: use them offline or with care.

**Windows XP SP3: unofficial.** `RapidR-2.123.0-winxp-x86-test.zip`. It is a test download: it is **not supported**, and we have tested it in a virtual machine, not on real old hardware yet. It needs plain Windows XP SP3, 32-bit, and a processor with SSE2 (a Pentium 4, an Athlon 64 or newer). Nothing else has to be installed on XP.

What works on plain Windows XP, and on Windows 7:

- RapidR Studio: the designer, the code editor, the Project pane, Help (F1), Settings, the right-click menus (right click, Shift+F10 and the Menu key) and the keyboard shortcuts.
- Running a program with F5, its output in Studio's Output pane.
- **Build (Interpreted App)**, made at once. A native build needs RapidR's own toolchain, which 32-bit Windows doesn't have, so Studio doesn't offer it there and never asks. The interpreted app runs the same program and needs nothing on the computer it is copied to.
- The programs you build, and `rapidr run` in a Command Prompt: forms, the console, files, big numbers, DLL calls and callbacks, `RFormEx`, right-click menus, and MIDI through Windows' own MIDI devices (`RMIDIPort`; a computer with no MIDI device lists none and says so).
- On XP, Open, Save and Browse for Folder are XP's own dialogs.
- English, Español and Português (Brasil) on both; 中文 (Simplified Chinese) on Windows 7, not on XP (see the table).

## Security

Four audits (the core with the JIT and the VM, the system with files, projects and Versions, the web, and the AI and MCP tools) found **13 problems: 2 high, 4 medium, 5 low and 2 informational. All 13 are fixed in this release** ([the reports](docs/security/)).

- **Versions never act outside the project's folder** (SEC-31, high; SEC-32 medium; SEC-33 low). A project that came with a version history pointing elsewhere isn't used: the Versions pane says "Versions are off for this project" and why. A version's links stay inside the project, and a project file can't point Run and Build outside its folder.
- **Web programs and Studio on the web** (SEC-34, high; SEC-35 medium; SEC-36 low; SEC-37 info). The frame that shows a program's web view can no longer be used by another site; a link can no longer drive Studio on the web; a program can't keep its windows' frame over Studio; a program in the browser gets only its own folder's files. **Rebuild and redeploy web programs made before.**
- **The AI tools read only the project's own files** (SEC-40, medium), a run that RAI or an AI app starts is sandboxed (SEC-41, low: no DLL call, `SHELL` or `RUN` unless you turn it on in Tools > Settings > AI, which asks first), and `set_property` sets one value (SEC-42, low).
- **Compiled code never overruns the machine stack** (SEC-50, medium). A deep recursion goes on interpreted with the same answer; past 100,000 nested calls it ends with the interpreter's own "stack overflow" error at the same line. Never a crash. A crafted bytecode file can't ask for unlimited memory (SEC-51, low). The code generator's own checker (SEC-52, info) runs in RapidR's tests and in the debug builds, and you can turn it on with `RAPIDR_JIT_VERIFY=1`; it stays off by default because it adds a quarter to the compile time. A bytecode file that is damaged is refused before it starts.
- **The JIT is checked against the interpreter.** Mutated programs were run both ways, JIT on and off, and gave the same answers and no crash: 6,066 programs. [check: the lead's brief says "29,617 mutated programs, 0 differences"; that number is not in the docs on disk. docs/security/audit-2026-11-05-core.md §2 says 6,066 verified mutated modules, 0 divergence, 0 crash. Use the final number once it is written down.]

Your keys stay in your system's keychain, and crash and hang reports stay on your computer; nothing is sent anywhere.

**Legal.** Every new part was checked for a licence that lets you sell your apps: the machine-code compiler library (pinned to exact versions), the MIDI library, the Chinese web font subset (SIL OFL, renamed so it doesn't use another company's trademark) and the small symbols font used only where a computer has no fonts. The reviews are in `docs/legal` (this is a check of licences and wording, not legal advice).

## Behaviour changes

Programs that were correct keep working. These are the changes that can stop a program that used to run, or that change an answer.

- **A global name declared twice is an error. Rename one of the two.** Every global name (a variable, `CONST`, `SUB`, `FUNCTION` or component, in any capitals) belongs to the program once, counting its main file and every file it `$INCLUDE`s. A `SUB`'s own variables and parameters may reuse a name. The message says where the first one is and what to do:

  ```
  main.rr:2:5: error: Identifier Total already used, try another name — it is declared in main.rr:1 already: a global is declared once in the whole program (its main file and every file it $INCLUDEs)
    hint: a global name is declared once in a whole program: rename one of the two, or delete the second (when two $INCLUDEd files both declare it, $INCLUDE only one of them)
  ```

  [check: this rule is not new. Tested today with `rapidr check` on the same small programs (a duplicate `DIM`, `CONST`, `SUB` and `FUNCTION`, a `DIM` against a component, a clash with an `$INCLUDE`d file): the 2.121.3 build already gives the same errors. What is new in Preview 6 is the hint line and the fix text, and the next two bullets. If a stricter rule landed that I could not find, change this bullet; otherwise keep it as "stays an error and now says how to fix it".]
- **A global that has a builtin's name is an error** (new). `CREATE Timer AS RTimer` made every `TIMER` the component; `SUB Run` hides the builtin `RUN`. The message names the builtin and a name to use: `Timer is the name of the builtin TIMER: the program can't tell them apart, so name the component PollTimer`. A variable counts only when the program reads the builtin through it (`DIM Len AS INTEGER` beside a `LEN(s)`). [check: not in CHANGELOG [Unreleased]; source is commit 1eb7ae73, docs/manual/language.md "Errors" and docs/errors-audit-2026-11.md.]
- **A block left open is an error** (new): a `SUB`, `FUNCTION`, `IF`, `FOR`, `WHILE`, `DO`, `SELECT`, `CREATE`, `TYPE` or `WITH` with no end is reported at the line that opens it, with the fix ("SUB Go (main.rr:1) has no END SUB"). Before, it was a silent mistake or a warning and the program ran. In a `.rr` program a block ends in the file it starts in. A classic `.bas` program gets the classic wording first, and no program is built. [check: same source as above.]
- **A file that is not UTF-8** (a `.rr` file) or that mixes UTF-8 with Windows-1252 bytes gets a warning at the first such byte, with the fix.
- **A bytecode file (`.rrbc`) made by 2.123.0 needs the 2.123.0 Runtime**; older ones still run.
- **`HEX$` of an `INT64` or `UINT64` shows 8 digits, or 16 when the number needs more than 32 bits** (2.122.1 always gave 16). `HEX$(x, 16)` gives 16.
- **In a program that uses `INT64`, `UINT64` or `UINT32`, a whole-number literal beyond 32 bits is an `INT64`.** A program without them keeps the classic 32-bit reading.
- **Runs started by RAI or an AI app are sandboxed**: no DLL call, `SENDMESSAGE`, `SHELL`, `SHELLWAIT` or `RUN`, unless you turn on Tools > Settings > AI > Programs the AI runs may use DLLs and SHELL. Your own Run (F5) is unchanged. `run_program` doesn't run code with errors.
- **A project file can't point Run and Build outside its folder**: a `main`, icon or build output folder naming a place outside it is set aside as the project opens, and Output says which.
- **Web programs made before must be rebuilt and redeployed** (security).
- **A radio button checked from code unchecks its group**, `FormStyle = fsStayOnTop` keeps a window on top, and an `RListBox`'s `OnChange` fires on a click. A program that relied on the old behaviour now behaves as classic programs expect.
- **In a RapidR program, a component with a `PopupMenu` and no handler opens it from the keyboard too** (Shift+F10, the Menu key). A classic program keeps the right click alone.
- **The mouse wheel over an `RScrollBar` in a RapidR program** moves it three `SmallChange`s a notch. A classic program's scroll bar stays as it was.
- **Menus in RapidR's looks have 24-pixel rows** (easier on touch and the web); the classic look keeps 20 pixels. **Project > Add File... is now Add Existing File...**.
- **`rapidr check` reads a Windows-1252 file** as the compiler does, instead of failing with "stream did not contain valid UTF-8".

## Known limits

- **The JIT** is on 64-bit Windows, macOS and Linux. The web and 32-bit Windows (Windows 7, 8 and XP downloads) run everything interpreted, with the same answers. A very large routine (an emulator's CPU step) takes 280 to 500 ms to compile, once, at the start. A loop that handles text or objects at every turn stays interpreted; `rapidr run --verbose` says where. On macOS, an app signed with the hardened runtime needs the `com.apple.security.cs.allow-jit` entitlement for its programs to be compiled; RapidR's own apps have it.
- **Windows XP** is unofficial and has the limits in the table above: no sound output, no screen reader, no AI providers over the network, Chinese as boxes, an SSE2 processor needed. Windows 7 and 8 are an alpha.
- **Portuguese and Chinese are beta**, AI translations no native speaker has reviewed. Their manual and components' Help are not translated yet.
- **RFormEx**: see-through windows and the hole are not on Linux yet; on Wayland the compositor decides what stays on top.
- **SQLite** refuses a `UINT64` above 9223372036854775807 with a message (pass it as text); MySQL takes it as `BIGINT UNSIGNED`.
- **DLL calls are real on Windows only.** RapidR does not emulate the Win32 API on other systems.
- **Not code-signed yet.** See Downloads for the one-time click on each system.
