# RapidR Preview 6.1 (2.123.1)

- **Build your app for every system, from RapidR Studio:** Windows (x64, ARM64 and 32-bit), macOS (Apple silicon and Intel Macs), Linux (x64 and ARM64) and the web, all from the computer you are on. The other systems' runners are checked against RapidR's signature before they are used, and a Mac app is signed by RapidR itself, so you don't need a Mac to make one.
- **One standard for the Windows API:** `$INCLUDE "RWin32.inc"`, built in, made from the Windows metadata Microsoft publishes. Your own include files keep working as they are.
- **Your web app can offer its own tools to AI agents in the browser** (`RAgentTools`), asking the person before anything changes. Today that is Chrome with WebMCP turned on in `chrome://flags`; more browsers as they add it.
- **Fixes and small things:** data grids read as tables to screen readers, `BringToFront` and `SendToBack`, `RoundRect` with a second colour, a working `CopyMode`, `RAudioOut.OnError`, a steady `RTimer`, and Studio's Settings in Spanish.

> **This is a Preview.** Try it and tell us what works, what breaks and what you need: [GitHub Issues](https://github.com/iBobX/RapidR/issues) for bugs, [Discussions](https://github.com/iBobX/RapidR/discussions) for questions and ideas.

Everything in [2.123.0](https://github.com/iBobX/RapidR/releases/tag/v2.123.0) is here. Please read [Behaviour changes](#behaviour-changes): an `RTimer` in a RapidR program now keeps a steady rhythm, which changes how a frame-driven program runs.

## Build your app for every system

Write your program once, and RapidR makes it into an app for each system, from the computer you are on. You don't need the other computers, a compiler or anyone's SDK ([the manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/build-for-every-system.md), [the design](https://github.com/iBobX/RapidR/blob/main/docs/build-core-design.md)).

**In RapidR Studio, Run > Build...** opens four steps on a list that is also the way between them:

1. **Where it runs:** Windows x64, ARM64 and 32-bit, macOS (one app for Apple silicon and Intel Macs), Linux x64 and ARM64, and the web. The first time, only this computer's system is ticked, so a first build works with no internet.
2. **Your app:** name, version, author, copyright, description, website, app id, category, kind (windows or console) and one icon, made into every size each system needs. **Project > Project Options** is this same step: one form for your app's details.
3. **What goes in:** the data files ticked, what is left out and why, **Add Files...**; under Advanced, the source and native code.
4. **Build:** a zip per system, or everything in one. A row of progress per app; Esc stops and keeps nothing half-made. Done lists the zips and says how to open the app the first time on each system, with **Show in Finder** (File Explorer, Files).

Every choice is saved in the project as you make it (there is no Cancel). **Build Again** (Ctrl+Shift+B) builds the saved choices with no dialog, and a note in the corner says how it went. Under 640 pixels wide the steps become one scrolling page. The dialog is in English, Spanish, Brazilian Portuguese and Chinese.

**The same from the command line**, for a script or another computer: `rapidr build tips.rr --targets windows-x64,macos,linux-x64,web`, or `--all` for every system RapidR builds for (windows-x64, windows-arm64, windows-x86, macos-universal, linux-x64, linux-arm64, web). RapidR's AI tools have `build_app` too, for RAI and for AI apps, and `RPROJECT` has `Copyright`, `Description`, `Website` and `Category`, and `Build "targets:<list>"`. A worked example is in [examples/apps/tip_calculator](https://github.com/iBobX/RapidR/blob/main/examples/apps/tip_calculator/main.rr).

**What you get.** `Name-1.0.0-<system>.zip` for each system (a `.tar.gz` for Linux, which keeps the "executable" mark), with `SHA256SUMS` beside them. Each has a `README.txt` that says how to open the app the first time on that system (in English or Spanish: `--language es`) and the runner's `THIRD-PARTY-NOTICES.txt`.

- **Windows:** the `.exe` with its icon, version information and a manifest that runs it as the person who starts it. One runner per processor.
- **macOS:** one universal `.app`, made for Macs with Apple silicon (macOS 11 or later) and Intel Macs (macOS 10.13 or later).
- **Linux:** an AppDir with `AppRun`, a menu entry, icons and `install.sh` (for you alone, no root; `--uninstall`).
- **The web:** the page, a web manifest and its icons, so it installs where browsers allow.

A data file's path can't leave the app (no `..`, no absolute path, no drive), links are refused, the program's source goes in only with `--include-source`, and a runner for the wrong processor is refused.

**Runners for other systems are fetched when you need them, checked, and kept** ([the manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/building-apps.md#where-runners-come-from)). An app starts from a **runner**, a small program made for one system. Each install carries its own system's; the first time you build for another one, RapidR fetches that runner (10 to 25 MB) from studio.rapidr.dev, and a runner is used only after three checks pass: the list's signature (minisign, against the release key built into RapidR), the list saying it is for exactly this RapidR's version, and the file having the size and SHA-256 the list gives. A runner you kept is checked again every time. After that, building for that system works offline. Fetching asks studio.rapidr.dev for three files, as a web page would; nothing else leaves your computer ([what is sent](https://github.com/iBobX/RapidR/blob/main/docs/manual/building-apps.md#what-is-sent)). `rapidr runners` shows which runners you have.

**RapidR signs a Mac app itself, on any system** ([the manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/building-apps.md#macos), [the design](https://github.com/iBobX/RapidR/blob/main/docs/macho-signer-design.md)). `rapidr build` used to run Apple's `codesign`; now RapidR's own signer, written in Rust from Apple's published format descriptions, does it, so signing no longer needs a Mac. It writes byte for byte what `codesign --sign -` writes, checked by tests. It is an ad hoc signature: no Apple Developer ID and no notarization, so the first time a Mac opens the app, macOS asks the person to confirm, and the zip's `README.txt` says how.

**On the web, for now, the web app.** RapidR Studio on the web builds your web app in the page (nothing leaves your computer); building the Windows, macOS and Linux apps from the browser comes in the next release. Today the full Build dialog is in RapidR Studio on the desktop, and `rapidr build` works on any system.

## One standard for the Windows API

If you have written programs that talk to Windows itself, you probably know this story. Everyone had their own `WIN32API.INC`: from a friend, from an old example, fixed by hand over the years, a constant added here, a declaration corrected there. The copies didn't agree, and two of them in one program clashed. A snippet that worked for someone else failed on your computer because your file had another name, another value, or nothing at all. Many of us lost hours to that, and nobody did anything wrong: there was no common file to share.

**First: nothing you have stops working.** A program with its own `WIN32API.INC` (or any other include file) compiles and runs exactly as before, through RapidR's RapidQ compatibility layer. Your files stay yours: RapidR never replaces or edits them, and nothing is switched for you.

**The change, if you want it, is one line:**

```basic
$INCLUDE "RWin32.inc"
```

`RWin32.inc` is built in: no file to find, download or copy, on every install. When you import an older program that includes a `WIN32API.INC`, the importer keeps your file, offers `RWin32.inc`, and lists every difference for the names your program uses: a constant with another value, a function your file called by another DLL name or with another number of arguments, a name `RWin32.inc` doesn't have. You decide. RapidR Studio asks after the import (**Keep my file** is the default answer); `rapidr import-rapidq myprogram.bas --rwin32` makes the switch in the copy and checks that it still compiles. Your original program is never changed ([the manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/windows-api.md)).

**Why it helps, in facts:**

- **One file for all of us.** An example, an answer or a snippet that uses `RWin32.inc` works on your computer the way it works on its author's.
- **Generated, not typed by hand.** RapidR's own tool makes it from the Win32 API metadata that Microsoft publishes (MIT licence): 55,710 constants, 3,675 structures and 6,506 functions of 29 Windows DLLs.
- **The classic names are there.** `MessageBox`, `GetWindowText`, `RECT`, `POINTAPI` and the rest mean what they meant. 1,496 of the 1,514 functions a widely used classic `WIN32API.INC` declares (98.8%) are in it under the same names, and the modern A and W names (`MessageBoxA`, `MessageBoxW`) as well.
- **Made for 64-bit and 32-bit Windows.** Every structure has both layouts, each checked against the sizes in Microsoft's metadata, and your program gets the one for the computer it is built for (tried on 64-bit Windows so far). `$IFDEF WIN64` is now defined for every 64-bit target, the web included.
- **A program pays only for what it uses.** A program with twenty Windows calls carries only those twenty declarations and compiles in well under a second. A name of your own always wins, so an old program's own `CONST` or `DECLARE` never clashes.
- **Tried on Windows 11 (ARM64):** `GetTickCount`, `GetSystemMetrics`, `GetComputerName`, `GlobalMemoryStatusEx` and `GetSystemInfo` through the generated declarations ([rwin32_system_info.rr](https://github.com/iBobX/RapidR/blob/main/examples/windows/rwin32_system_info.rr)).

**If something is missing or looks wrong, please tell us** in [Discussions](https://github.com/iBobX/RapidR/discussions) or an [issue](https://github.com/iBobX/RapidR/issues). The file is generated, so one fix reaches everyone.

RapidR is free and open, made so that everybody can learn to program, and we grow it together, people and AI alike. Thank you for being part of it.

## Your web app can offer its own tools to AI agents in the browser

**`RAgentTools`** lets a web app made with RapidR offer tools to AI agents that run in the browser, such as a browser's own assistant or an extension: `AddTool`, `Start`, `OnToolCall`, `Reply` ([the manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/agent-tools.md), example [web/agent_tools.rr](https://github.com/iBobX/RapidR/blob/main/examples/web/agent_tools.rr)). It works with the WebMCP draft of the W3C Web Machine Learning Community Group; not a W3C Standard. It is a draft: it can change, and today only some browsers offer it. Where a browser does not, `Available` is 0 and your program carries on.

A change an agent asks for is asked of the person first, and what your windows show is shared only when you say so. RapidR Studio on the web offers its own tools to the browser's agents the same way ([AI apps](https://github.com/iBobX/RapidR/blob/main/docs/manual/ai-apps.md)).

WebMCP is the name of a draft specification of the W3C Web Machine Learning Community Group; RapidR uses the name only to say which draft its browser feature follows. W3C and browser names belong to their owners. RapidR is independent of all of them and is not made, sponsored or endorsed by any of them ([LEGAL.md](https://github.com/iBobX/RapidR/blob/main/LEGAL.md)).

## Smaller things

- **`BringToFront` and `SendToBack` on every component on a form** ([the manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/components.md#stacking-bringtofront-and-sendtoback), example `examples/gui/drawer.rr`): a component over or under its siblings, drawn on top **and** taking their clicks where it covers them (a drawer panel opened over the workspace). The layout doesn't move. The same on the desktop, in native builds, in the interpreter and on the web.
- **`RDBGrid.Col`, the current column:** a click on a cell sets it, Left and Right move it (scrolled into view), the program reads and sets it. Example `examples/data/grid_cells.rr`.
- **`RoundRect` takes a second colour** ([the manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/graphics.md#rounded-boxes-roundrect), example `examples/graphics/round_rect.rr`): `RoundRect x1, y1, x2, y2, rx, ry, Color, Fill` draws a one-pixel border in `Color` and fills the inside with `Fill` (-1: only the border). A card or a pill is one call. The seven-argument form is exactly as before.
- **`CopyMode` works** ([the manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/graphics.md#copymode-how-a-picture-meets-what-is-there), example `examples/graphics/copy_modes.rr`): `Draw`, `StretchDraw` and `CopyRect` combine the picture with what is already there as the destination's `CopyMode` says, the 15 raster operations of Windows, on an `RCanvas`, an `RBitmap`, an `RImage` and a form's surface, interpreted, native and in a browser. Before, every mode copied.
- **`RAudioOut.OnError (Code, Message)`** ([the manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/directx-and-media.md#sound-made-sample-by-sample-raudioout), example `examples/media/audio_errors.rr`): the sound says what went wrong, on the program's thread, a moment after it happened: `aeNoDevice`, `aeDeviceLost`, `aeBadSetting`, `aeUnderrun` (at most four a second) and `aeNeedsClick` (a browser waits for a click or a key). A program without `OnError` is unchanged.
- **`RTimer.FixedRate`** ([the manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/graphics.md#a-picture-every-20-milliseconds), example `examples/gui/steady_timer.rr`): ticks every `Interval` milliseconds exactly, by the clock. At `Interval = 20` that is 50 ticks a second, where the old rhythm ticked about 28. See [Behaviour changes](#behaviour-changes).

### Fixed

- **Grids reach screen readers as tables.** An `RDBGrid`'s and an `RStringGrid`'s rows hold their cells, each named with its column's heading and its place ("Name, Ada, row 2 of 10, column 1 of 3"), the fixed row's cells are column headings, and the current cell has the screen reader's focus, so each arrow key says the new cell. Before, a data grid's rows were only "Row 0 of 400" with nothing under them. An `RListView`'s report view says each row's other columns with their headings, and in a browser the cells carry ARIA's row and column numbers and headings.
- **A classic program can write a CONST again after `$OPTION WEAKTYPE ON`** ([the manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/compatibility.md#a-const-written-again-option-weaktype), example `examples/rapidq/weaktype/weaktype.bas`). A constants file ported to the classic language, which writes some of `RAPIDQ.INC`'s names again, stopped with `CONST variable ANSI_CHARSET already defined` and hundreds more. Through the compatibility layer it now compiles: with the option on, the last value wins. With it off (the default) a second CONST is still an error. The same on the interpreter, native builds, the web and in Studio's Problems.
- **A classic program's `QTIMER` keeps its beat:** the next tick is one period from where the last was *due*, not from where its handler ended. A tick that falls due while a handler runs waits for it and runs the moment it ends.
- **The manual and Help said an `RTimer` ticked "every Interval milliseconds".** They now say what it does: the `Interval` is counted in Windows' steps of 15.6 ms, and how the ticks follow one another depends on the timer.
- **Tools > Settings > General in Spanish:** the labels' column is as wide as its longest label in the dialog's language, so *Las notificaciones se quedan* no longer runs under its choice, and the Debug and Notifications choices are as wide as their longest item.

## Behaviour changes

Programs that were correct keep working. These are the changes that can alter how a program runs or an answer it gives.

- **An `RTimer` in a RapidR program ticks every `Interval` exactly, by the clock, by default.** `Interval = 20` is 50 ticks a second, not about 28. A tick that falls due during a long handler runs the moment it ends, and the ones missed besides it one after another, up to 250 ms behind; a handler never runs inside itself, and a timer that is behind runs one handler a turn, so a heavy handler on a short `Interval` never starves the window's events. A frame-driven program that ran slow now runs at its `Interval`. **`FixedRate = 0` is the old rhythm.** A classic program's `QTIMER` is not changed by this.
- **`rapidr build` makes the version `1.0.0` by default** and names each zip `Name-1.0.0-<system>.zip`; set the version in Project Options or with `--app-version`.
- **`$IFDEF WIN64` is defined for every 64-bit target**, the web included, so a program's structures have the same sizes there as on 64-bit desktops.

## Known limits

- **Building the Windows, macOS and Linux apps from RapidR Studio on the web** comes in the next release; the web Studio builds the web app today (see above).
- **The first time an app is opened on a system, the system may ask the person to confirm.** Each zip's `README.txt` says how to open it there. A Mac app has an ad hoc signature (no Apple Developer ID, no notarization).
- **`RWin32.inc` is not all of Windows:** GUID constants, COM interfaces, functions with a variable number of arguments (`wsprintf`) and a few functions that take a large structure by value are not in it, and some areas are left out for now (cryptography, GDI+, ODBC, WinHTTP, IP Helper). You can always `DECLARE` what you need next to the include. A call into a Windows DLL runs on Windows only; on other systems the program compiles and the call stops with a message that names the function.
- **`RAgentTools`, and AI apps in RapidR Studio on the web,** need a browser that offers the WebMCP draft. Today that is Chrome with `chrome://flags/#enable-webmcp-testing` turned on (tried with Chrome 156 on 2026-11-08); elsewhere Studio says so and the switch stays off, and RapidR Studio on the desktop works with any AI app.
- Everything in [2.123.0's Known limits](https://github.com/iBobX/RapidR/releases/tag/v2.123.0) still applies.
