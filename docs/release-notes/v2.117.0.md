# RapidR 2.117.0

**RapidR's first public release.**

RapidR runs and builds RapidQ programs. It targets full compatibility with
RapidQ on all three of its runtimes — the **native compiler** (your program
as a native executable), the **interpreter** (the RapidR Runtime, and
standalone executables that carry it) and the **web** (the same program in a
browser) — and an existing RapidQ program behaves as it does under RapidQ.

RapidR also goes further than RapidQ, without changing what RapidQ programs
do: SQLite with parameter binding, JSON and HTTP, a data-science stack (data
frames, arrays, charts), high-DPI screens, screen-reader accessibility,
themes, the web, and more.

RapidR is not a clone or a port of RapidQ. It is an original implementation,
written from the ground up in pure Rust, that is compatible with RapidQ.

## What's in this release

The last public snapshot was v2.8.1; everything below came since. The full
history is in [CHANGELOG.md](https://github.com/iBobX/RapidR/blob/main/CHANGELOG.md).

**RapidQ compatibility, checked against RapidQ itself**

- RapidQ's own compiler (RC.EXE) runs in a Windows VM as the ground truth.
  Numbers, PRINT (nine decimals, 32-bit whole numbers, the comma), STR$,
  rounding and integer stores, the bit operators, division by zero, string
  functions' edge cases, default colours and more now print exactly what
  RapidQ prints, natively, interpreted and in the browser.
- The whole RapidQ language: TYPEs with methods, constructors, events and
  inheritance, `TYPE … EXTENDS QBUTTON`, arrays of components, function
  pointers, GOTO / GOSUB, DATA / READ, SUBI / FUNCTIONI, `$RESOURCE`,
  memory functions (memory-safe), console statements, RapidQ's DIM grammar
  and type suffixes, `RAPIDQ.INC` built in.
- **Every RapidQ object but OLE**: every visual component (grids, list and
  tree views, headers, outlines, MDI forms, splitters, owner-drawn lists
  and combo boxes, …), the dialogs, menus, QREGISTRY (Windows' registry on
  Windows), the printer, sockets, QMYSQL, the tray icon (QNOTIFYICONDATA)
  on every platform, QCGI, QCOMPORT, QDOWNLOAD, QMIDI with a built-in
  synthesizer, QWAVE, QVIDEO playing AVIs, QCDAUDIO, QGLASSFRAME, and the
  components of RapidQ's include libraries (QFORMMDI, QBEVEL, QDIGDISPLAY,
  QDIRLISTVIEW, QDOCKFORM, …) built in.
- **DirectX**: QDXSCREEN, QDXIMAGELIST, QDXTIMER, QDXSOUND, QDXJOYSTICK
  (gamepads) and Direct3D retained mode (`.X` models, lights, textures,
  wraps, shadows, transparency) on RapidR's own software rasterizer —
  everywhere, the browser included.
- RapidQ's example corpus: the 123 programs that use only the API RapidQ's
  Windows and Linux versions shared all compile, and run alike natively and
  interpreted.

**RapidR's own UI kernel, on the desktop and the web**

- Every window is drawn by RapidR's UI kernel (winit, vello, parley,
  AccessKit): RapidQ's classic Windows look by default, the same on macOS,
  Windows, Linux and in the browser. FLTK is gone.
- **Themes**: `$THEME Modern`, `Dark`, `HighContrast`, `Auto`;
  `Application.Theme` at run time.
- **High-DPI**: programs keep RapidQ's pixels; everything is drawn sharp at
  the screen's scale; SVG images wherever RapidQ takes a bitmap.
- **Accessibility**: keyboard navigation and a screen-reader tree for
  every program (VoiceOver, Narrator, NVDA; an ARIA mirror on the web).
- **Responsive layouts**: `Anchors` and size constraints.
- **The web** runs on the same kernel only: windows on a canvas, checked
  pixel by pixel and tree by tree against the desktop's; SQLite compiled to
  WebAssembly; Noto fallback fonts for symbols, CJK and emoji; nothing
  contacts a third party.

**The RapidR Runtime and installers**

- Installers for Windows (x64, ARM64), macOS (universal) and Linux
  (x86_64, aarch64; `.deb` and `.tar.gz`), and the web IDE as a static
  `.zip`.
- The **RapidR Runtime**, installable alone, runs `.rrbc` programs and
  sources: `.rrbc` files run on a double click, `.rr` / `.bas` files open
  in the IDE with a Run action, downloaded files ask once. Bytecode
  format 3 says which runtime a program needs.
- `rapidr run`, `open`, `info`, `ide`, `setup`, `notices`. Programs run,
  the IDE works and standalone executables build with **no Rust
  installed**; native builds compile offline against the shipped runtime
  sources once `rapidr setup` has installed Rust (it never changes your own
  toolchain). On Windows the SDK ships its own linker (LLVM-MinGW).

**Extensions**

- `RSQLite` (SQLite itself, everywhere) and QMYSQL with `?` parameter
  binding — no SQL injection.
- Data science: `RNum` (arrays), `RDataFrame` (tables), `RPlot` (charts
  as PNG, in a QIMAGE or on the page) — one implementation, the same
  results natively, interpreted and in the browser — and `RJson`, `RHttp`.
- Web-only components: `RWebView`, `RDOM`, `RJavaScript`, `RWebStorage`,
  `RWebAudio`, `RWebVideo`, `RWebNotification`, `RWebGeolocation`,
  `RRouter`.
- VB's `#If`, `i++`, `+=`; `#!/usr/bin/env rapidr` scripts.

**Your programs are yours**

- Every build writes `THIRD-PARTY-NOTICES.txt` beside the executable (or
  into the web build), generated from the build's real dependency graph:
  ship it with the program and that is all the licences ask.
- Nothing copyleft, no cryptographic code and no data-licensed content is
  compiled into a program: HTTPS uses the operating system's TLS.

**Documentation**: a new [user manual](https://github.com/iBobX/RapidR/blob/main/docs/manual/README.md)
(also installed with the SDK), a rewritten README and contributor manual.

## Known limits

- **OLE / COM** (QOLECONTAINER, QOLEOBJECT) isn't implemented: such
  programs compile; the objects do nothing and warn.
- **Windows API calls** (`DECLARE … LIB "user32"` and the like) aren't
  emulated: they are compile errors naming RapidR's portable alternative.
  Many of RapidQ's examples call DLLs directly. Your own libraries can be
  called from native builds (not from the interpreter or the web).
- **Unsigned installers**: macOS Gatekeeper and Windows SmartScreen will ask
  (see below).
- **The IDE is early.** The desktop IDE (written in RapidR) and the web IDE
  design forms, edit code and run programs; the full IDE — IntelliSense, a
  debugger, linked data components, AI assistance through an MCP server —
  is the next milestone ([ROADMAP.md](https://github.com/iBobX/RapidR/blob/main/ROADMAP.md)).
  The AI component for your own programs (`RAI`) and mobile come after.
- **Printing** makes PDFs: sent to the printer through CUPS on macOS and
  Linux and through the browser on the web; on Windows saved as a PDF.
- **Linux** needs OpenSSL 3: Ubuntu 22.04 / Debian 12 or newer.
- **The Intel half of the macOS apps** is checked by inspection only; it
  hasn't run on an Intel Mac before this release.
- `ON ERROR` (VB's) is accepted and ignored.

The SDK includes the runtime. Each install is for you alone and needs no
administrator rights (the `.deb` packages install system-wide).

**Start working right away:** install, open the IDE (Windows: Start menu >
RapidR IDE; macOS: RapidR; Linux: RapidR IDE in your applications), write a
program and press Run. No other software is needed to run programs or to make
standalone executables (`rapidr build prog.bas --interp`). Native builds
(`rapidr build prog.bas`) compile your program with Rust: `rapidr setup`
installs it once, after asking.

**File types:** a `.rrbc` (a compiled RapidR program) runs on a double click;
a `.rr` or `.bas` opens in the IDE, and "Run" (Windows) or "Open With > RapidR
Runtime" (macOS, Linux) runs it. A program downloaded from the internet asks
once before it runs. On macOS and Linux a script that starts with
`#!/usr/bin/env rapidr` runs directly.

**Unsigned downloads:** this release is not code-signed. On macOS, the first
time, right-click the app and choose Open (or System Settings > Privacy &
Security > Open Anyway). On Windows, SmartScreen may say "Windows protected
your PC": choose More info > Run anyway.

**Verify a download:** `SHA256SUMS` lists every file's SHA-256
(`shasum -a 256 -c SHA256SUMS`, or `Get-FileHash` on Windows).
`rapidr-2.117.0.cdx.json` is the release's software bill of materials
(CycloneDX).

**Tested on** macOS (Apple silicon), Windows 11 (ARM64) and Ubuntu 24.04
(ARM64, Wayland and X11): the conformance suite on every backend, the GUI
test programs headless and with real windows, what screen readers see; the
browser suites in Chromium; each installer smoke-tested on its system (x64
Windows and x86_64 Linux under emulation).
