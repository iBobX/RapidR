# RapidR 2.119.0 — Preview 2

> **This is a Preview.** Try it and tell us what works, what breaks and what you need — [GitHub Issues](https://github.com/iBobX/RapidR/issues) for bugs, [Discussions](https://github.com/iBobX/RapidR/discussions) for questions and ideas.

RapidR runs and builds RapidQ programs. It targets full compatibility with
RapidQ on all three of its runtimes — the **native compiler** (your program as
a native executable), the **interpreter** (the RapidR Runtime, and standalone
executables that carry it) and the **web** (the same program in a browser) —
and an existing RapidQ program behaves as it does under RapidQ.

RapidR also goes further than RapidQ, without changing what RapidQ programs
do: a data-science stack (data frames, arrays, charts), an AI stack, SQLite and
MySQL, high-DPI screens and accessibility, and more.

RapidR is not a clone of RapidQ. It is an original implementation,
written from the ground up in pure Rust, that is compatible with RapidQ.

## What's new

The second Preview. Where the first one gave you the IDE, this one gives it an
AI assistant, a data engine, a deeper debugger and a lot more of RapidQ's
own programs running as they do under RapidQ.

- **An AI assistant in RapidR Studio, and `RAI` in your own programs.** Choose
  Anthropic (Claude), OpenAI, DeepSeek or any OpenAI-compatible server — a model on
  your own computer too — and ask about your project, have the assistant propose
  changes as diffs you accept or reject, or say "Build me a tip calculator" and see
  the program before anything is written. It is **off until you turn it on**, keeps
  your key in the system's keychain (never in a project or a program), and shows
  exactly what it sent. [The manual's chapter](https://github.com/iBobX/RapidR/blob/main/docs/manual/ai-assistant.md).
- **Data science, fast and easy.** `RDataFrame` runs on RapidR's own typed, multicore
  engine: a million rows load, filter, sort and group in **23 ms** on an Apple M4 Max
  (pandas 3.0.1: 372 ms on the same table; ten million rows take 0.27 s). New linked
  components — `RCSV`, `RDataSource`, `RDBGrid`, and `DataSource` / `DataField` on
  edits and labels — put a CSV or JSON file in a grid with no code, and **RapidR
  Studio's designer shows the data live** while you design.
  [Data science with RapidR](https://github.com/iBobX/RapidR/blob/main/docs/manual/data-science-with-rapidr.md).
- **A debugger that opens your data.** Rest the mouse on any value, or look in
  Variables or Watch, and open it like a tree: arrays, TYPEs, forms and their
  components, data frames as tables, as deep as you like, with changes in blue.
  **Set Next Statement** (retry or skip a failed line), **Step Into Specific**,
  and a leaner VM: a 10-million-iteration loop in about 0.6 s (it was 1.09 s), Studio
  waiting for you at 0.25 % of a core (it was 10 %).
  [Debugging](https://github.com/iBobX/RapidR/blob/main/docs/manual/debugging.md).
- **Events and the debugger, checked against RapidQ itself.**
  - A breakpoint in an event handler stops on every event, and **Continue** works whenever the program is paused.
  - The paused program's window stays on screen and can be brought to the front (**Debug ▸ Show Program Window**).
  - Setting `Text`, `Checked` or `Position` from code fires exactly the events RapidQ fires, and an error inside a handler behaves as it does in RapidQ: each rule was tested on RapidQ's own compiler first.
  - New **`OnEnter` / `OnExit`** focus events on every component that takes the focus.
  - Stepping, loops, recursion, breakpoints in include files and editing a value while paused are all walked and tested on desktop and web.
- **Studio follows your system's look.** It starts dark on a dark system and switches with it. Your programs can follow it too, with the new `Application.OnThemeChange` event.
- **Examples that just work where RapidR is installed.** Opening an example gives you your own copy in `Documents/RapidR/Examples`, built apps carry the data files they use (a built `linked_data` opened from Finder shows its rows), and examples say clearly when a file couldn't be read or written.
- **Showcase: eight programs in pure RapidR**, each running on the desktop, as a built app and in the browser ([Showcase](https://github.com/iBobX/RapidR/blob/main/docs/manual/showcase.md)):
  - a **MIDI visualizer**: a 3D scene that reacts note by note to a song composed by a RapidR program, its MIDI reader written in BASIC;
  - **fireworks** with about 1,600 sparks;
  - a **signal lab**: an oscilloscope plus a spectrum, its FFT written in BASIC;
  - a **3D planet** with its moon;
  - **Monte Carlo π**;
  - **four datasets with the same numbers**;
  - **snake**;
  - a **Markdown notes** app.
- **Rich text.** `RRichEdit` formats each character and paragraph (`SelAttributes`,
  `Paragraph`), keeps the formats while the user types, undoes and pastes them, reads
  and writes RTF files, and tells screen readers what it looks like — settled
  against RapidQ's own compiler.
  [Rich text](https://github.com/iBobX/RapidR/blob/main/docs/manual/rich-text.md).
- **RapidR Studio is written in RapidR**: about 9,900 lines of RapidR BASIC, built from the same public components your programs can use (code editor, inspector, docking panels, designer, debugger session, AI), and the same code runs on the desktop and in the browser.
- **Studio in the browser is the same Studio.** A program window bigger than the page
  is never cut off (the page scrolls), the desktop's and the browser's windows are
  pixel for pixel the same, screen readers read the web inspector, and a debugger step
  takes 15 to 30 ms on both (the budget is 50).
- **More of RapidQ runs as RapidQ runs it.** `$INCLUDE` finds files where RapidQ finds
  them, on every system, and the importer copies every include; Windows file names
  (`data\notes.txt`, `OPEN.BMP`) work on macOS and Linux; and RapidQ's 428 examples were
  run one by one beside RapidQ's own compiler in Windows, then on macOS, Linux and the
  web — a long list of small differences fixed, each one checked against RC.EXE.
  [Windows](https://github.com/iBobX/RapidR/blob/main/docs/rapidq-corpus-status.md), [macOS, Linux and the web](https://github.com/iBobX/RapidR/blob/main/docs/rapidq-corpus-status-unix.md).
- **New examples**: `data/linked_data`, `data/million_rows`,
  `data/json_source`, `debugging/shop`, `gui/richtext`, `gui/sales_dashboard`,
  `gui/focus_events`, `ai/rai_models`, `ai/ask`, `rapidq/shapes`, and the eight in `showcase/`.
- **A new manual page, [Why RapidR](https://github.com/iBobX/RapidR/blob/main/docs/manual/why-rapidr.md)** (what RapidR does best,
  with measured numbers and their conditions), chapters for the AI assistant, data
  science and rich text, a clearer Getting started (which download to take; `run` against
  `build-bc` against `build`), and a README and examples list in reading order.

The SDK includes the runtime. Each install is for you alone and needs no
administrator rights (the `.deb` packages install system-wide).

**Start working right away:** install, open the IDE (Windows: Start menu >
RapidR Studio; macOS: RapidR Studio; Linux: RapidR Studio in your applications), write a
program and press Run. No other software is needed to run programs or to make
standalone executables (`rapidr build prog.bas --interp`). Native builds
(`rapidr build prog.bas`) compile your program with Rust: `rapidr setup`
installs it once, after asking.

**File types:** a `.rrbc` (a compiled RapidR program) runs on a double click;
a `.rr` or `.bas` opens in the IDE, and "Run" (Windows) or "Open With > RapidR
Runtime" (macOS, Linux) runs it. A program downloaded from the internet asks
once before it runs. On macOS and Linux a script that starts with
`#!/usr/bin/env rapidr` runs directly.

## Known issues in this Preview

- Some RapidQ programs that rely on Windows internals don't run yet: 32-bit pointers kept in LONG variables, x86 machine code run through CallWindowProc, DLL callbacks, 32-bit DLLs shipped with a program ([the status page](https://github.com/iBobX/RapidR/blob/main/docs/rapidq-corpus-status.md)).
- Not yet: `FormStyle = fsMDIChild`, shaped windows (`SetWindowRgn`), `$UNSAFEMEM`, native library calls on macOS and Linux. Windows DLL calls work on Windows only.
- The high-contrast theme meets WCAG AA (4.5:1); AAA (7:1) is planned.
- In RapidR Studio, Cmd/Ctrl+Z doesn't undo while the Properties pane or the toolbox has the keyboard; click the designer or the code first, or use the toolbar's Undo.
- On Linux, Studio and programs read the system's light or dark look when they start, but don't yet follow a switch made while they run.
- In web Studio, an example you edited stays edited in the browser's storage; "Copy again from the original" is desktop-only for now.
- Rarely (about once in twenty launches seen in testing), a 3D window (`RDXScreen`) stays on its first frame. Close it and run it again.
- A weather showcase is waiting for `RHttp` to send request headers (weather services ask apps to identify themselves).
- RapidR Studio starts in about 0.4 s on the desktop (it was 0.28 s before the AI, data and debugger features); speeding it up is planned.
