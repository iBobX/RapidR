# Legal review: one standard set of Windows API declarations for RapidR, 2026-11-07

Reviewer: RapidR's conservative legal reviewer (zero-risk rule; not a lawyer, not legal advice).
Question: can RapidR ship one standard set of `DECLARE ... LIB "user32"`, `CONST` and `TYPE` declarations, and from what source?
Method: public sources only (GitHub raw files, NuGet's public package index, crates.io, Microsoft web pages). Nothing downloaded into the repository; copies of the licence files were read in the scratchpad only. No repository file was changed except this one.

## Verdict (one line)

**Yes, ship it, generated by RapidR's own tool from the Win32 metadata that Microsoft itself publishes under MIT OR Apache-2.0 in `windows-rs` (not from the NuGet `.winmd`, not from `WIN32API.TXT`), with the MIT notice below.** Hand-written additions (c) only for gaps. Community includes (d) only with a written provenance statement. Do **not** commit or ship `scratch/parro-inc/WIN32API.INC`.

## Risk table

| Option | Risk | One-line reason |
|---|---|---|
| (a1) Generate from `windows-rs` (`metadata/win32/*.rdl`, or the `windows-sys` crate source) | **Low** | Microsoft's own repo, plain MIT / Apache-2.0 files, Microsoft already distributes exactly these declarations as `windows-sys` |
| (a2) Generate from the `.winmd` in the NuGet package `Microsoft.Windows.SDK.Win32Metadata` | **Medium** | The package's own licence file is the Windows SDK EULA, which contradicts the README's "winmd is MIT" |
| (b) Ship the classic `WIN32API.TXT` / a Rapid-Q port of it | **Medium** (legal) and **high** (quality) | Real grant, but not a standard licence, text only seen on secondary copies, old 32-bit content, and the local port has an unknown author |
| (c) Write our own from public documentation | **Low** (legal) | Names, signatures and numbers are facts; the real danger is copying from memory, so it must be tool- and data-driven |
| (d) Accept community include files | **Low** if the author wrote it and says so; **High** if it descends from any file in (b), RapidQ's `windows.inc`, Wine, MinGW, Free Pascal, JEDI or Delphi | The grant is only as good as the contributor's own right to give it |

## (a) win32metadata

What the sources say:

- `README.md` (Licensing): "MIT: all metadata assemblies (e.g. `Windows.Win32.winmd`)" and "all tooling ... in the Microsoft.Windows.SDK.Win32Metadata NuGet package". "Windows SDK: all Windows headers (e.g. RecompiledIdlHeaders) and IDL files in this repository and in the aforementioned NuGet package."
- `LICENSE` is MIT, "Copyright (c) Microsoft Corporation", but it starts with a disclaimer: "This repository does not change the licenses of the original SDK headers used to generate the metadata." GitHub's detector therefore shows the licence as "Other / NOASSERTION".
- The NuGet `.nuspec` (version 71.0.45-preview, 2026-11-05) says `<license type="file">sdk_license.txt</license>` and `requireLicenseAcceptance=true`. That file (`licenses/sdk_license.txt` in the repo) is the "Microsoft Windows SDK for Windows 10" licence: distributable code only if listed in REDIST.TXT, only for Microsoft platforms, end users must agree to terms that "protect it at least as much", and you must indemnify Microsoft. Incompatible with MIT redistribution if it applied to the winmd.
- The GitHub release has **only** the two `.nupkg` files; there is no stand-alone MIT-labelled `.winmd`.
- `microsoft/windows-rs` (the Rust projection, same Microsoft team): root `license-mit` and `license-apache-2.0`, no SDK disclaimer; crate `windows-sys` 0.100.0 declares `license = "MIT OR Apache-2.0"`; the repo now holds the whole Win32 surface as text (`metadata/win32/*.rdl`, 691 files, e.g. `extern fn BuildTrusteeWithNameA(...)` with `#[library("ADVAPI32.dll")]`). RapidR already depends on `windows-sys` (THIRD_PARTY_NOTICES.md), so the chain is already accepted.

Assessment:

- Microsoft is the copyright holder of the SDK headers and of the metadata, so it can license the metadata as MIT; the README says it did. The risk in (a2) is the *conflicting* NuGet licence file, not who owns what. Under zero-risk, avoid (a2).
- (a1) removes that conflict: Microsoft itself publishes the same names, signatures and constants as MIT OR Apache-2.0 source, and millions of builds redistribute them.
- Are the generated declarations a derivative work? Treat them as one. They reproduce the metadata's content, only in RapidR's syntax; the generator and the type mapping are RapidR's own. So the MIT condition applies: keep "Copyright (c) Microsoft Corporation" and the permission notice with the generated files. Because the content is mostly facts (see (c)), this is belt and braces.
- Residual risk: a few SDK headers include third-party-origin material (for example OpenGL). Low; the declarations are still interface facts. Skip sections you do not need.

## (b) WIN32API.TXT

The header (quoted in your question, and visible in `scratch/parro-inc/WIN32API.INC` lines 28-38): "Copyright (C) 1994 Microsoft Corporation ... You have a royalty-free right to use, modify, reproduce and distribute this file (and/or any modified version) in any way you find useful, provided that you agree that Microsoft has no warranty, obligation or liability for its contents."

- It is a real copyright grant (use, modify, reproduce, distribute; no copyleft; no field-of-use or OS limit; commercial use not excluded: "any way you find useful"). It does not grant "sublicense" in words, but it runs with every copy to every recipient, so redistributing the file as a separate, clearly marked file is within it. RapidR must **not** relabel it MIT; it would stay under its own header and be listed in THIRD_PARTY_NOTICES.md.
- Why it is only medium, and not what I would pick:
  1. I could not find the text on any official Microsoft page. Microsoft's VB6 page (aa261280) only describes the file; the wording was seen on a third-party copy. The KB article for the VB5 update (Q178020, WIN32API.EXE) says only "AS IS" and says the original had incomplete or wrong declares.
  2. It is not an SPDX/OSI licence; nobody has tested it. The grant is to "this file", so every change you want (RapidR syntax, 64-bit pointers) rests on "any modified version".
  3. The local file is **not** Microsoft's file: it is a third-party Rapid-Q port (headers `'-- Win32 API declarations for Rapid-Q`, `$OPTION VBDLL ON`, `$DEFINE INTEGER SHORT`, 15,594 lines). Its porter's changes have their own copyright and no stated licence; the folder name suggests a community author. Microsoft's grant does not cover that person's work.
  4. Content is VB4-era: `Long` for handles, no 64-bit, known errors. Quality and WOW both lose.
  5. LEGAL.md says RapidR "contains no code ... of Microsoft"; shipping it would make that false.
- State of the repository today: the file is **untracked and not ignored** (`?? scratch/`); `git log --all` finds no WIN32API file in history. Do not `git add -A` with it there; delete it or add `scratch/` to `.gitignore`.

## (c) Write our own from public documentation

- Function names, parameter order and types, structure layouts and constant values are facts or are dictated by the platform: *Feist v. Rural* (no protection for facts), merger / *scenes a faire*, 17 U.S.C. 102(b); in the EU, *SAS Institute v. World Programming* (CJEU C-406/10, 2012): the functionality of a program and a programming language are not protected. Counter-weight: in *Google v. Oracle* (593 U.S. 1, 2021) the Supreme Court assumed API declaring code might be copyrightable and decided on fair use, so the US point is not formally settled. That is why we still add the attribution under (a).
- The documentation itself is licensed: Microsoft's docs repos (`MicrosoftDocs/sdk-api`) are CC BY 4.0 for text and MIT for code. Facts taken from it need no licence; if prose or samples are ever copied, CC BY 4.0 attribution applies. Do not copy prose.
- The real danger is not the law but **copying from memory** (a person or an AI writing `windows.h` / `winuser.h` / MinGW / Wine text from recall). Wine is LGPL, MinGW-w64 headers are mixed (ZPL, public domain, some Wine-derived), Free Pascal and JEDI are LGPL/MPL, Delphi's `Winapi.*` is proprietary. Rule: every hand-written line is checked against the Microsoft documentation page or the windows-rs data, and a similarity check (as done in `rapidq-review.md` section 9) against those projects is run before release.

## (d) Community-made include files

Needed before accepting any (CONTRIBUTING.md already says contributions are MIT and "you wrote it yourself or otherwise have the right"):

1. A statement in the PR or issue, in the contributor's own words: "I wrote this myself" or the exact source and its licence; their name or handle; the date.
2. Licence MIT (or CC0 / public domain) for the whole file, stated in the file header.
3. Not derived from: `WIN32API.TXT` or any Rapid-Q port of it (the author may add nothing the grant does not allow, and cannot relicense Microsoft's part), RapidQ's `windows.inc` ("(c) RealSoftware" line; already barred by CONTRIBUTING.md and clean-room.md), Windows SDK headers, Wine, MinGW-w64, Free Pascal, JEDI, Delphi, or an AI chat paste with no source.
4. A similarity check against the sources in (b) and (c) before merge; record the result in the PR.
5. Entry in `docs/legal/` provenance list and THIRD_PARTY_NOTICES.md only if anything non-MIT is inside (it should not be).

## Recommendation

1. Build a generator (RapidR's own code, MIT) that reads `windows-rs` `metadata/win32/*.rdl` (or the `windows-sys` crate source) at a **pinned commit/version** and writes RapidR include files (`$INCLUDE`able `DECLARE`, `CONST`, `TYPE`), one file per DLL group (user32, kernel32, gdi32, comctl32, shell32, advapi32, ole32, winmm ...). Map pointer-sized types (handles, `LONG_PTR`, `SIZE_T`) to RapidR's pointer-sized integer so 64-bit is right; that is technical, but it is also where the old files were wrong.
2. Record the pinned commit and the SHA-256 of the input in the generated header and in `docs/legal/` (provenance).
3. Put the notice below at the top of every generated file and in THIRD_PARTY_NOTICES.md (and the program-level THIRD-PARTY-NOTICES.txt when a program includes the file).
4. Keep (b) out. Keep `scratch/parro-inc/` out of git and out of any package.
5. Update LEGAL.md and the `rapidq-review.md` row ("Windows constants ... not protected") to say RapidR ships Win32 declarations generated from Microsoft's MIT-licensed metadata and still contains no Microsoft SDK header text.
6. Do not name the include `windows.inc` (RapidQ's file name) or `WIN32API.TXT`; a neutral name such as `win32.rr` / `RWin32.inc` is enough. "Win32" and "Windows" are used descriptively only.
7. Re-run the lawyer check whenever the pinned source changes licence (`cargo`/`crates.io` licence field for `windows-sys`, repo `license-mit`).

## What I could not check

- The wording of the real `WIN32API.TXT` on an official Microsoft page (not found online; only secondary copies and the local port).
- Whether `windows-rs`'s `.rdl` files carry any hidden per-file terms: the sampled files (`aclapi.rdl`, `metadata.rdl`) have none; the repo-level licences apply. Re-check the pinned commit when the generator is written.
