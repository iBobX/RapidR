### 4. Privacy and security

| Question | Result | Evidence |
|---|---|---|
| Are toasts scrubbed of secrets "like the Output pane"? | **NOT AS CLAIMED (F1)** | The claim is made in `docs/research/notifications.md:65`, `docs/design-guidelines.md:173` and `ide/notify.inc:16-17`. I looked for the code: `grep -i scrub\|redact\|mask\|secret` over the four component files finds nothing. `Notify.Show` (`crates/rapidr-value/src/panels/notify.rs:892-908`) and `Update` (`:910-922`) store and announce the text as given; `Toast()` in `ide/notify.inc:147-150` passes it straight on; `RNotifyBar.Ask` (`notifybar.rs:210-228`) the same. What exists in the project is `rapidr_value::secrets::mask` (`crates/rapidr-value/src/secrets.rs`), a registry of values RapidR was told are secrets (keychain reads, database passwords, AI keys), applied today to a running program's output (`crates/rapidr-session/src/program.rs:268`) and to RAI replies (`rapidr-ai/src/rai.rs:3119`), not to Studio's own `OutputLine` (`ide/panels.inc:934-939` only scrubs for the crash note) and not to toasts. In practice nothing secret reaches a toast today: every toast Studio shows is a fixed phrase plus file names, or the chat title in "Deleted "<title>"." (`ide/aichats.inc:571`), and a title can hold what the person typed first, which the chat list already shows. So there is no live leak, but the promise is not true as written, and a program using `RNotify` gets no masking at all. |
| Is the history only in memory? | **PASS** | `Notify.history: Vec<Entry>` (`notify.rs:258`), last `history_size` (default 50, `HistorySize` property up to 500) kept in the component's in-process model; no `serde`, file, network, process or `env` use in `notify.rs`, `notifybar.rs` or the two kernel files (I searched `std::fs`, `File::`, `OpenOptions`, `std::net`, `reqwest`, `http`, `TcpStream`, `Command::`, `std::process`, `env::var`, `open_`, `spawn`, `telemetry`, `analytics`; the only hits are the kernel's internal `send(cx, ...)` event dispatch). The one value stored is a preference number, `NotifyStay` (0, 1 or 2) in Studio's per-user settings (`ide/project.inc:400`, `:436`). Two sentences that Studio already wrote to the Output (for example "{file} was deleted outside Studio...", `ide/external.inc:192-193`) still go to the Output and its in-memory crash-note ring, as before this lane. |
| Telemetry, phoning home | **PASS** | None. No network code in any new file; the web wiring adds no request; the manual and Studio say "nothing was sent" where it matters. |
| Can a program put clickable content that executes something? | **PASS** | Actions are captions only: `parse_actions` (`notify.rs:858-860`) splits on `\|` and keeps two; `plain()` and `mnemonic()` only handle `&`. A pressed action fires `OnAction(Id, Index, Key)` in the program's own code. The component opens no URL, runs no command, loads nothing. Studio's own handler dispatches by fixed keys: `reload` (`external.inc:356`), `ai-made` (`ai.inc:2661`), `chat-undo-N` (`aichats.inc`), `gone`; the text of a message never decides what runs. "Run It" on the assistant's toast is the same as F5, as the old banner button was. |
| Text injection in toasts | **PASS, one hardening (F5)** | The text is drawn as plain text; no Markdown, HTML or link is parsed (only the `&` mnemonic in action captions). Control characters and Unicode direction overrides are not removed, so a file name with a direction override could be shown in a misleading way in "{names}". Low risk (it is what the file is called, and the editor tabs already show the same names) but cheap to close. |
| Can RAI or an AI app press an action? | **PASS, one registry gap (F4)** | `Press` is documented for RAI and AI apps ("the same members a person's program uses") and does what a click does, so it can start whatever the program's `OnAction` does. Studio's own toast stack is not newly exposed to MCP or RAI by this lane (no change in `rapidr-ai`, `rapidr-mcp`). |
| Keyboard focus taken by a toast | **PASS, one wording note (F3)** | The guide says a toast "never takes the keyboard" (`design-guidelines.md:171`). One toast does, on purpose: the assistant's "made this program" toast gets the keys for Enter = Run It (`ide/ai.inc:2573-2579`, `:2640-2653`; stated in `docs/manual/ai-assistant.md:586`). Nothing runs until the person presses it. Say so in the guide. |
| Test hooks | **PASS** | New steps `notify:say`, `notify:press`, `notify:retire` ride the existing `--do` test-step list (`ide/shell.inc:343-344`, same as `versions:`, `layout:`, `ext:`); the clock override is read through `rapidr_testmode::var("RAPIDR_TEST_CLOCK")` (`panels.rs:76`), the gated reader reviewed in `review-2026-10-30-test-mode.md`. |
