# RAI training corpus: what the last build made

Generated by `tools/rai_train/build_corpus.py` on 2026-10-29 (seed 20261029, scale 1.0), against `RapidR 2.121.3  (repo 9ee817b9)`. The data is in `$RAI_ROOT/data` (never committed); this file is its report. Every tool answer in the corpus is the real one of RapidR's own tools (`rai_check` replays them with no model); every program a model is trained to write compiles; a model's slip shown for context is never learned.

**3627 items (conversations), 13054 training rows** (12501 train, 553 valid): one row per learned assistant turn, because mlx-lm's `--mask-prompt` learns only the last message of a row; 376 rows longer than 8192 tokens were left out (93 conversations whose writing turn was that long, whole).

## Left out on purpose (hold-out and legal)

- The recipes that are the eval's own `apps/` solutions: calculator.rr, csv_viewer.rr, drawing_pad.rr, password_generator.rr, quiz_game.rr, server_manager.rr, stopwatch.rr, tip_calculator.rr, todo_list.rr, unit_converter.rr. Training on them with the eval's prompts would teach the answers.
- Recipes topically next to a school task (`school/cpu-emulator`): cpu_stack.rr, cpu_step.rr, cpu_timing.rr, disassembler.rr.
- `examples/gui/stopwatch.rr`, `examples/web/todo.rr` (the eval's stopwatch and to-do apps), `examples/rapidq/` (RapidQ-derived), programs over 160 lines, Windows-only programs.
- Everything outside this repository: no RapidQ corpus, no `.reference/`, no cloud-model output (the eval transcripts included), no other project.
- `tests/ai-eval/**` and its reference solutions are the hold-out: `validate_corpus.py` checks every prompt and program against them.
